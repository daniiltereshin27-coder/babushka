# Админка и калькулятор Babushka Exchange

Проверка локальной серверной версии по разделам 2–7 клиентского ТЗ. Браузерный сценарий создаёт отдельный сервер и временную базу SQLite. Все контакты, новые инструменты, дополнительные правила и города в сценарии тестовые.

## Что проверено

| Путь | Результат |
|---|---|
| Каталог → выбор стороны | Созданы криптовалюта только для отдачи, наличная валюта только для получения и безналичный способ для обеих сторон. Загрузка и замена иконки прошли через форму. Мобильный список учитывает сторону. Выключение стороны блокирует открытую форму. |
| Страна → город → правило | Созданы страна с первым городом и дополнительные города. Дубликат с другим регистром оставляет название в форме и показывает ошибку. Кнопка в строке города переносит его в новое правило. Поиск города принимает слова в разном порядке. |
| Доступность | Серверные проверки охватывают приём, выдачу, обе операции, паузу страны и снятие паузы с сохранением настроек каждого города. В браузере отдельно проверены пауза правила, страны, выдачи и выключение валюты при открытой заявке. |
| Каталог правил | В списке 31 правило. Проверены поиск, фильтр по фактической доступности, страницы, сохранение при активном фильтре и переход к существующему обратному направлению. |
| Расчёт | Проверены минимум, максимум, выход за лимиты, граница диапазона и ввод с обеих сторон. Переключение с Москвы на Дубай меняет результат. Работают криптообмен без города и блокировка пары без правила. |
| Таймер | В браузере часы переведены на 61 секунду. Зафиксирован новый запрос с последней редактируемой стороной «Получаете», введённое значение сохранилось. |
| Открытая заявка | Курс менялся через админку и отдельно без уведомления вкладки. В обоих случаях новые суммы требуют подтверждения. Имя, Telegram и согласия сохраняются. При паузе кнопка отправки заблокирована. |
| Сохранение | Сервер проверяет имя, Telegram, три согласия, пару, город, лимиты и последний курс. Запись содержит принятые суммы, курс и названия инструментов. При потере ответа повтор вернул прежний номер. Проверены сохранность после перезапуска и защита от повтора с другими данными. |
| Интерфейс | В Chrome проверены разделы админки на ширинах 320, 390, 768 и 1280 px, основной сценарий — при 1440 px. Горизонтального переполнения страницы в проверенных разделах нет. В выборе города проверены стрелка вниз и Enter. |

## Контрольный пример

У обоих тестовых инструментов базовая цена 1 USD. Для города Янтарный установлены лимиты 100–5 000 единиц отдачи, поправка −2% и поправка −1% от 1 000 включительно.

| Отдаёт | Получает |
|---:|---:|
| 99,99 | Заявка недоступна |
| 100 | 98,00 |
| 999 | 979,02 |
| 1 000 | 990,00 |
| 1 001 | 990,99 |
| 5 000 | 4 950,00 |
| 5 001 | Заявка недоступна |

При вводе 990 со стороны получения сервер рассчитал 1 000 к отдаче. После изменения верхней поправки на −0,5% форма показала 995 к получению. Перед отправкой поправку изменили ещё раз, до 0%. Клиент подтвердил 1 000 к получению. Сервер выдал BX-000001. Номер относится к изолированной тестовой базе.

## Границы проверки по ТЗ

- Котировки локальные. Охват валют в Xe, давность котировки, доступность тарифа и запасной источник для криптообмена требуют проверки с выбранными источниками и доступом заказчика.
- Рассчитанный обмен сохраняется в SQLite. Отправка и повтор доставки уведомлений в рабочую группу Telegram остаются отдельной интеграцией. Повтор клиентского HTTP-запроса проверен отдельно.
- В локальной админке свободный доступ. До публикации нужны авторизация менеджеров и ограничение доступа к административным API.
- Сценарии проверены на русском. Английская и испанская версии, редактор текстов и юридических документов, официальные контакты и материалы для криптокарт остаются частью полного ТЗ.
- Этот прогон охватывает форму рассчитанного обмена. Дополнительные формы нестандартного направления и обратной связи пока проверяют введённые данные на клиенте.

Повторить модульные проверки можно командой `node --test tests/*.test.*`. Полный сценарий в Chrome запускается командой `node qa/admin-calculator/check.mjs`. При другом расположении браузера или Playwright пути задаются через `CHROME_BIN` и `PLAYWRIGHT_MODULE`.
