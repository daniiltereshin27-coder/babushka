# Babushka Exchange

## Фоновая музыка

Предоставленный MP3 сохранён в `assets/background-music.mp3`. При каждой загрузке звук запрашивается включённым, трек начинается сначала, громкость 45%, повтор по кругу. Громкость задаётся через `MUSIC_VOLUME` в начале main.js.

Браузер может отклонить автозапуск со звуком. Тогда музыка запускается после первого клика/нажатия клавиши либо по кнопке «Включить музыку» слева внизу. Кнопка выключает музыку независимо от видео. Ручное выключение действует до следующей перезагрузки. При скрытии вкладки музыка приостанавливается; при возврате возобновляется только если пользователь её не выключил. Без JS доступны стандартные аудиоконтролы.

Ограничения autoplay: https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay

Локальный прототип hero-блока на HTML, CSS и vanilla JavaScript. Сборка, npm и фреймворки не нужны.

## Запуск

Из папки проекта:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080. Альтернатива: `npx serve .`.
Можно открыть `index.html` двойным щелчком, однако HTTP-сервер предпочтительнее для проверки загрузки видео.

## Файлы

- `index.html` — слои сцены, шапка, навигация, настоящие текст и кнопки, секция `#exchange`.
- `styles.css` — оформление, адаптив, каскадное появление, CSS-мигание, reduced motion.
- `main.js` — проигрывание, фолбэки, повтор интро, пауза, бургер, обработчик обмена.
- `assets/` — предоставленные исходные PNG и MP4; они не изменены.
- `assets/logo-placeholder.svg` — временный белый знак-косынка. Файл логотипа не был приложен. Для замены положите свой `assets/logo.png` и поменяйте `src` у изображения внутри `.brand`.
- `assets/opt/` — место для оптимизированных файлов.
- `qa/` — снимки четырёх размеров экрана и отчёт проверки.

## Как работает сцена

Восстановлен самый первый вариант прототипа: исходные intro.mp4, loop.mp4 и PNG-постеры. Первое открытие: тёмная сцена → intro → появление интерфейса примерно на 2.6 секунде → loop. При каждом заходе и каждой перезагрузке intro снова начинается с тёмной сцены.

На стыке intro → loop нет затухания: слой переключается после готовности первого кадра loop. Повторы исходного loop используют два буфера с перекрытием 300 мс, как в первоначальной версии. Генерация Higgsfield и последующие изменения перехода в этой версии не используются.

Для повторного просмотра интро достаточно обновить страницу. Старый флаг sessionStorage.bx_intro_seen больше не используется.

При отказе автоплея или тайм-ауте intro включается CSS-мигание постера на 3 секунды. Если интерфейс уже виден или отказал loop, остаётся светлая статичная сцена. При `prefers-reduced-motion: reduce` источники видео вообще не назначаются, а интерфейс показан без анимаций. При отключённом JS доступны светлая картинка, навигация и обычные якорные ссылки. Если сам `main.js` не загрузится, защитный таймер через 6.5 секунды покажет интерфейс.

Loop приостанавливается при скрытой вкладке, уходе hero за экран и по кнопке паузы. На мобильном вся сцена сдвинута вниз на 110px с плавной маской сверху: это сохраняет лицо и кота ниже текста. Все медиаслои сдвигаются одинаково, поэтому переходы остаются совмещёнными.

## Что менять

В начале `main.js`:

```js
const REVEAL_AT = 2.6;          // секунды от начала intro
const SWAP_BEFORE_END = 0.12;   // за сколько секунд до конца готовить loop
const INTRO_TIMEOUT = 3000;    // ожидание готовности intro, миллисекунды
const LOOP_CROSSFADE_MS = 300;  // затухание между двумя loop-буферами
const USE_OPTIMIZED_ASSETS = false;
```

При изменении `LOOP_CROSSFADE_MS` поменяйте также `.is-blending` в CSS. 

Тексты — в `index.html`. Цвета и шрифты — в `:root` в `styles.css`. Шрифты Playfair Display 700 и Manrope 500/700 запрашиваются из Google Fonts с `display=swap`; при отсутствии сети используются Georgia/Arial.

`onExchangeClick()` пишет `exchange-click`, переносит фокус и плавно прокручивает к `#exchange`. Именно сюда можно добавить будущий видеопереход. Обмен и отправка заявки сейчас не выполняются. Остальные пункты меню содержат заданные якоря `#about`, `#partners`, `#rules`, `#contacts`; соответствующие разделы не входят в этот прототип.

## Оптимизация

В среде создания не установлены ffmpeg и cwebp, поэтому прототип использует исходники, как разрешено заданием. Отдельных 1280-версий сейчас нет. После установки ffmpeg выполните из папки проекта:

```sh
mkdir -p assets/opt
for name in intro loop; do
  for width in 1920 1280; do
    ffmpeg -i "assets/${name}.mp4" \
      -vf "scale=${width}:-2" -c:v libx264 -crf 26 -preset veryfast \
      -pix_fmt yuv420p -an -movflags +faststart \
      "assets/opt/${name}-${width}.mp4"
  done
done

for name in scene-dark scene-lit; do
  ffmpeg -i "assets/${name}.png" -vf "scale=1920:-2" \
    -frames:v 1 -c:v libwebp -quality 80 "assets/opt/${name}.webp"
done
```

Если в ffmpeg нет libwebp, изображения можно создать через cwebp:

```sh
cwebp -q 80 -resize 1920 0 assets/scene-dark.png -o assets/opt/scene-dark.webp
cwebp -q 80 -resize 1920 0 assets/scene-lit.png -o assets/opt/scene-lit.webp
```

Затем:

1. В `main.js` установите `USE_OPTIMIZED_ASSETS = true`.
2. В `index.html` замените обе ссылки `assets/scene-dark.png` (preload и img) на `assets/opt/scene-dark.webp`, а `assets/scene-lit.png` — на `assets/opt/scene-lit.webp`. Обновите размеры img на 1920×1086.
3. Обновите страницу. При ширине окна менее 1280px или `navigator.connection.saveData` JavaScript выберет видео 1280; иначе — 1920. Выбор выполняется один раз при загрузке, чтобы поворот устройства не обрывал сцену.

## Проверка и ограничения

Смотрите `qa/REPORT.md`. Проверены четыре размера, интро при первом входе и перезагрузке, кнопки, меню, остановка обоих буферов и запасные сценарии. Реальное устройство iPhone в Low Power Mode не использовалось; отказ `play()` проверен симуляцией. Lighthouse не запускался. На локальном первом открытии PerformanceObserver зарегистрировал CLS 0; это не заменяет Lighthouse на будущем хостинге. Видео и изображения пока исходного размера, поэтому оценка скорости публикации будет зависеть от оптимизации и сервера.

## Сцена обмена

Кнопка «Обменять» открывает сцену стола с демонстрационным калькулятором. Три проверенных ролика Seedance 2.5 привязаны к фазам исходной петли 1,5 / 3,5 / 5,5 секунды. При загруженных файлах ожидание ближайшего входа обычно не превышает двух секунд; сам подъём камеры длится около пяти секунд.

Первый кадр каждого ролика выровнен с исходником; небольшая коррекция масштаба плавно снимается в первые 0,75 секунды. После завершения сохраняется последний кадр текущего ролика. Отдельный постер используется для неподвижного режима и ошибок загрузки. В reduced motion и при приостановленной анимации форма открывается сразу.

Финальный ракурс высокий и наклонный, не строго 90°. Часть реквизита уходит за край при движении камеры. Варианты с заметным растворением в середине отклонены и в сайт не включены.

Калькулятор: суммы с точкой или запятой, USDT TRC20/ERC20, BTC, ETH, USD, EUR, смена направлений, условный выбор получения и города. Все курсы и комиссия 1% учебные. Заявки не создаются и не отправляются. Кнопка результата открывает только локальный диалог.

Новые файлы: `desk.js`, `desk.css`, `flight.js`, `assets/desk-flight-1.mp4` … `desk-flight-3.mp4`, `assets/desk-final.jpg`. Исходные intro/loop, музыка и затемнение шапки сохранены. Проверки: `qa/desk/REPORT.md`.
